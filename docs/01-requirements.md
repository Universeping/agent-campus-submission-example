# 需求与成功标准

业务理解版本：v0.1.0。已实现 schemas、完成条件校验和三个独立工具，Agent 尚未实现。模型已选定；框架最终选择待确认。字段见 [数据约定](06-data-contracts.md)，估时和事实检查范围见 [工具说明](07-tools.md)。

## 业务需求

- 选择项目：短视频脚本 Agent；题号待用户补充。
- 目标用户：需要将产品资料转化为短视频脚本的创作者。
- 业务目标：生成有事实依据、满足时长与品牌约束的可编辑脚本，并能够依据检查反馈修改。
- 用户输入：文本形式的主题、受众、平台、目标时长、风格；当前 `TaskInput` 五项必填，不设隐含默认值，入口后续负责将缺项转为补充请求。
- 业务资料：本地文本资料，参考官方平台规则及产品说明，配合明确标记的合成案例、自定品牌与创作规则；不依赖图片、音频或视频，不要求运行时联网抓取平台。
- 预期交付：JSON 与 Markdown，包含标题、分镜、旁白或字幕、分镜及预计总时长、来源引用、风险与任务状态。
- 首版范围：Python CLI、文件/终端 JSON 输入、单 Agent、本地检索/估时/事实与品牌及平台规则检查、DeepSeek V4 Pro 入口、离线 Mock、终端及文件输出、Trace 和可执行测试。
- 缺信息处理：返回具体补充请求并结束本次任务；用户完善 JSON 后重新提交，首版不恢复此前会话。
- 模型：用户指定 DeepSeek V4 Pro；官方标识 `deepseek-v4-pro`。框架建议采用 LangGraph 小型状态图，尚待最终确认与版本锁定。
- 暂不实现：视频生成、配音、会话恢复、网页编辑器、HTTP API、多 Agent 或生产级 Runtime；API 与前端作为后续迭代复用同一业务核心。
- 最小正常案例的时长口径已确认：目标时长为上限，不超过 30 秒；暂不设置严格下限。具体估时公式待实现，不冒充平台规定。
- 已约定任务状态：`completed`、`needs_input`、`incomplete`、`failed`；非完成状态必须说明原因。完成状态要求最终脚本与通过的估时、规则报告同时匹配版本及内容指纹。
- 已实现估时口径：timing-v1，4 字符/秒、明确停顿与转场、每镜至少 2 秒；不等同于实际配音。
- 首版事实核验：素材原文逐句匹配、同分镜引用、标题/画面/旁白受控表达、显式品牌禁用词；超范围返回无法核验，不声称覆盖任意改写。
- 待明确：调用预算、真实平台/产品组合及模型/框架依赖版本。

## 资料准备与分类

1. 发布平台：抖音、快手的官方规范可作为规则参考。
2. 产品素材：剪映、必剪的官方说明可作为产品事实候选来源；不能把产品说明当作发布平台规则。
3. 项目自定：品牌表达、标题/字幕长度、语速和结构建议明确标为自定配置；无官方依据时不写成官方要求。
4. 合成案例：可构造缺资料、工具失败和冲突场景，注明生成方式；真实输出与 Trace 仍须实际运行得到。

公开来源、核对日期和读取限制见 [来源登记](../data/sources.md)。目前仅建立最小合成测试资料，官方来源数据集尚未生成；来源登记不等于已经实现相应规则检查。

## 第一条最小任务

先以 [normal/input.json](../examples/normal/input.json) 驱动开发，使用 [materials.json](../data/materials.json) 与 [brand_rules.json](../data/brand_rules.json)。不引入额外产品事实、平台规则或新工具。

用户指定：素材 P01 仅包含“支持为视频添加字幕”，规则 B01 为“不得虚构功能或效果数据”，受众为新手，风格轻松，总时长不超过 30 秒。输入主题具体化为介绍字幕功能，平台采用“通用短视频”测试场景，不代表特定平台政策。

成功须同时满足：

1. 输出包含标题、分镜、旁白、预计时长、来源和任务状态。
2. 产品功能表达得到 P01 支持，不能仅检查引用 ID 存在。
3. 最终工具估算总时长不超过 30 秒，分镜与总时长可核对。
4. 标记完成前，最终版本必须经过估时和规则检查且通过；修改后重新检查，不复用旧版本结论。

本用例仅是完整考核的首个正常场景，不替代后续缺信息、无素材、工具失败、超时长修正及执行上限验证。
