# 复盘

当前 CLI Agent 已实现六动作循环、三个本地工具、版本保护、配置、Trace 和来源导出。最新日志记录 119 项测试通过（105 项业务、14 项独立诊断），八个产品 profile 的 Mock CLI 完成；CapCut 网页端与必剪 iOS 两条真实正常路径完成，缺关键信息、工具失败、空资料和无关资料均有实际记录。超时长案例有修订、重检及明确未完成退出，无最终修订成功证据。结论及原始材料见 [效果验证](03-evaluation.md)。

以下为实际代码与运行结果中的工程观察。个人学习感受、独立尝试和实际用时仍由候选人补充，不能用这些观察代填。

## 已观察到的问题与处理

检查报告必须绑定版本与内容，只有稿次不能防止误改正文。运行器负责分配版本和指纹，保存新稿后只读新稿报告；同稿复查失败也会撤销旧通过。历史真实正常路径保存了 v1、v2 及重检；当前超时长路径保存了 v1 至 v4，最终 v4 不沿用 v3 的通过报告。

Python 数据类型与模型可见工具协议不同。项目补充六动作 description/JSON Schema、严格解析、调用 ID 配对和无效响应反馈。真实模型曾同时申请多个动作，程序拒绝本轮执行，模型纠正后继续。

事实检查采用原文和封闭表达，能限制无依据扩写，但曾误拒“它支持为视频添加字幕”这样的合理表达。这是当前业务限制，不能将所有检查拒绝都宣传为发现虚假事实；也不能仅凭引用 ID 存在就允许任意结论。

运行环境也影响验证：用户完成依赖安装并在本机直连后成功运行，客户端现默认直连、可选择系统代理。后续也发生间歇连接失败。CapCut 成功中的网络恢复由程序重试完成；P01 工具失败后的查询调整则由模型选择，二者不能混为模型决策证据。

超时长实测经历 7.6→5.3→2.25 秒，压缩曾丢失唯一事实，被规则工具拒绝；最终 v4 恢复原文后遇连接错误并耗尽 12 步，没有最终检查。离线 v4 虽可行，不能代替原任务的检查或改写原始结果。自定义评估 failed 保留，同时说明它已有修订和明确未完成证据，不能把该分类直接等同于考核整项不达标。

20/10 预算复跑在最初两次请求即连接失败，未进入业务工具。独立诊断随后记录宿主列表成功、聊天超时，具体网络原因仍未知；没有证据归因为模型推理慢。一次简化请求漏带头曾导致错误判断，核对源码后确认生产 JSON 请求头一直正确，已纠正且未修改生产客户端。

## 范围取舍与能力边界

资料扩充选择按 profile 隔离产品/客户端、保留来源，而非直接混合四品牌。原包兼容通过不能证明业务语义正确；Canva 两类字幕及网站表述仍需区分，审阅配置暂缓一条，原始内容不改。未引入数据库或向量检索，先验证资料、规则、来源和范围绑定。

批量场景区分“第一稿直接满足短时长”与“超时后修订”，以及“看到空授权范围直接补充”与“观察实际空检索结果后补充”。当前真实记录已展示两种资料不足场景中的实际空检索；自动评估仍不替代文案质量和理由充分性的人工阅读。

先完成 CLI 核心链路，不引入前端、会话恢复、多 Agent 或生产级 Runtime。LangGraph 只承担图调度，业务完成条件由程序维护。Mock 用来验证分支，真实 Trace 用来证明模型观察后作出选择。

8 个 profile 中已有 2 个真实正常成功，其余 6 个仅有 Mock CLI；成功超时修订和重复运行稳定性尚未证明。官方发布平台规则、开放域事实核验等能力未实现，均如实列为边界，不把它们或前端、数据库、向量检索列为原题必交缺口。
