# 复盘

当前最小 CLI Agent 已实现六动作循环、三个本地工具、版本保护、配置、Trace 和来源导出。105 项测试通过，八个产品 profile 的 Mock CLI 完成，真实连接受阻。更早两条真实成功为历史。个人学习感受与用时由候选人补充。

## 已观察到的问题与处理

检查报告必须绑定版本与内容，只有稿次不能防止误改正文。运行器负责分配版本和指纹，保存新稿后只读新稿报告；同稿复查失败也会撤销旧通过。真实记录保存了 v1、v2 和重新检查过程。

Python 数据类型与模型可见工具协议不同。项目补充六动作 description/JSON Schema、严格解析、调用 ID 配对和无效响应反馈。真实模型曾同时申请多个动作，程序拒绝本轮执行，模型纠正后继续。

事实检查采用原文和封闭表达，能限制无依据扩写，但误拒了“它支持为视频添加字幕”这样的合理表达。这是当前最明显的业务限制。下一步应整理可验证的同义表达案例，比较受控改写或语义判断的误报与漏报，不能简单把校验放宽为只检查引用 ID。

运行环境也影响验证：依赖安装和 API 连接在执行环境中受网络限制。用户完成安装并在本机直连运行，现默认仅 DeepSeek 客户端直连，可选择系统代理。保留连接失败记录，区分网络失败、工具失败和模型决策。

## 本轮取舍与未完成项

资料扩充选择按 profile 隔离产品/客户端、保留来源，而非直接混合四品牌。原包兼容通过不能证明业务语义正确；Canva 两类字幕及网站表述仍需区分，审阅配置暂缓一条，原始内容不改。未引入数据库或向量检索，先验证资料、规则、来源和范围绑定。

本轮更新提示词并补充批量场景后，进一步区分“第一稿直接满足短时长”和“超时后修订”，以及“看到空授权范围直接补充”和“观察实际空检索结果后补充”。自动报告标记未覆盖，不为了填满验收表而编造失败。下一步在宿主终端复跑新提示词真实案例，再决定是否需要人工首稿修订评估入口。

先完成 CLI 核心链路，不引入前端、会话恢复、多 Agent 或生产级 Runtime。LangGraph 只承担图调度，业务完成条件由程序维护。Mock 用来验证分支，真实 Trace 用来证明模型观察后作出选择。

资料已扩充，尚缺真实模型在产品 profile 下的验证、超时长修订、官方发布平台规则和重复运行统计。后续先补真实决策场景，再评估前端展示；增加会话恢复时需同时处理资料/规则/估时配置变化带来的检查失效。
