# AI 辅助与个人贡献

## 分阶段 AI 使用范围

以下按发生阶段记录；“尚未实现”等措辞仅指对应阶段，当前状态见末尾核心循环记录。

- 使用 Codex 辅助解读考核要求、讨论 CLI / HTTP API、ReAct 循环与工具接入的概念。
- 使用 Codex 检查本机 Git 配置，并生成本起始仓库的目录、忽略规则和文档骨架。
- 用户通过 GitHub 页面创建远程仓库；Codex 配置本地远程地址并准备首次提交。首次提交前检查了目录文件、Markdown 相对链接、行尾空白及忽略规则；这些检查不构成业务测试。
- 用户确认文档同步规则后，Codex 创建 `AGENTS.md`，约定需求、方案、评估、AI 使用、复盘和证据的更新时机，并同步 README。按用户要求建立本地 `note/` 目录、加入 Git 忽略规则；通过差异格式、文档链接、忽略规则及已跟踪文件检查验证，这些属于仓库配置检查。
- 用户确认短视频脚本 Agent 的首版范围和 Python 模块结构后，Codex 创建七个 Python 文件及依赖清单占位，同步需求、方案、评估、目录说明和协作规则。文件仅含模块说明，业务流程正在讨论，尚未定义 schemas 或实现功能。验证限于 Python 语法、文档本地链接、差异格式和 `note/` 忽略规则。
- 用户指定 DeepSeek V4 Pro，并要求固化讨论结果后，Codex 查阅 DeepSeek、LangGraph、抖音、快手和剪映等官方页面，登记来源与读取限制，更新业务理解基线 v0.1.0、三个工具设计、CLI 输入输出和后续迭代范围。按授权创建本地空密钥 `.env` 与可提交模板，将带版本号的讨论 spec 保存在被忽略的 `note/`。LangGraph 仍为拟用方案，未安装依赖、生成业务数据集或发起模型请求。
- 用户明确 P01、品牌约束、新手/轻松/30 秒需求及四项验收标准后，Codex 写入三份最小 JSON 资料并同步文档；将主题具体化为介绍字幕功能，平台设为通用短视频测试场景。资料标为合成，未关联真实品牌。验证仅涉及 JSON 解析、最小内容与 ID 一致性、文档链接及忽略规则，未生成脚本或调用模型。
- 用户提出六类交换结构并强调第二稿不能沿用第一稿检查后，Codex 实现 `schemas.py`，补充分镜、品牌规则、问题定位、检索与工具错误、运行模式和未完成原因；增加版本/内容指纹绑定与完成约束，使用标准库避免提前绑定框架。新增 15 项单元测试并保存实际结果到 `examples/schema-validation/unittest-001.txt`，全部通过。报告为单元测试人工构造，不代表真实估时、规则判断或模型输出。
- 用户明确三个工具接口、关键词检索、可解释估时及受限事实检查后，Codex 实现实际本地函数、JSON 加载器与独立命令入口；增加兼容的品牌禁用词字段、22 项工具测试和实际运行输出。完整 37 项测试通过。示例脚本为人工测试输入，未冒充模型输出；尚未调用 DeepSeek 或实现 Agent 循环。
- 用户核对工具是否已向模型暴露后，Codex 在本次阶段提交前补充实现边界：内部 schemas、工具执行和面向模型的 description/参数 JSON Schema 是不同层次；其中面向模型的调用适配与循环仍待实现。记录后续从可信状态注入资料、规则和时长上限的约定。
- 用户选定 LangGraph 并要求先讨论接入层与中心循环后，Codex 核对 LangGraph 与 DeepSeek 官方文档，更新框架选择，记录状态、节点、控制动作、版本失效、反馈协议和调用预算的讨论稿。未实现接入代码、安装依赖或发起模型调用；控制动作和预算仍待确认。
- 上述工具阶段完成时，数据结构、完成条件校验和本地工具已实现，Agent 与真实模型验证尚未开始。

## 核心循环实现与验证

用户确认单 Agent、六动作、可信状态、版本重检、预算和 LangGraph 后，Codex 编写 model.py、agent.py、main.py、trace.py，补充配置、原生函数调用与参数校验、状态图、CLI、错误处理、输出和依赖锁定。修改 schemas 的补充问题字段与工具“至少表达一条事实”的检查，维护相关文档。代码和测试由 AI 辅助生成及修改，不记为候选人独立编码。

Codex 创建项目 .venv 并准备依赖；执行环境下载受网络限制，用户自行成功安装 requirements、在本地填写密钥。Codex 随后使用实际安装的 LangGraph 1.2.18 运行测试，最终 79 项全部通过，无跳过，证据为 [unittest-001.txt](../examples/agent-validation/unittest-001.txt)。单测 HTTP 响应为测试替身；八条 Mock 案例使用真实图与本地工具，不能证明真实模型效果。

Codex 的真实连接尝试因 DNS 失败而结束，相关结果保留。用户在宿主终端执行正常任务和工具失败注入任务，发现启用本机代理时无法访问 DeepSeek，直连后成功。Codex 增加仅作用于该客户端的代理开关，默认直连；没有改写用户密钥或全局代理。

两次真实成功结果由模型实际生成；Codex 读取 result/history/trace/run，核对工具错误后的模型恢复、首稿修改、最终稿两项重检、版本和指纹。另实际运行 real 模式缺输入校验，未调用模型。生成 [运行索引](../examples/agent-validation/README.md)、文件摘要与复核报告，原始 Trace 保持不改。

验证同时发现原文规则误拒正常路径的合理改写，记录为检查器限制；没有把它包装成识别了虚假功能。真实超时长修订、开放域事实检查与重复运行稳定性尚未证明。

## 用户资料包评估与接入

候选人自行提供四产品、40 条事实、20 条规则和八组配置，并要求评估使用。Codex 阅读原包与验证脚本，复跑 140 项确定性检查，在官方/开发者页面或官方索引核对来源；原始 fact 为中文转述，规则为项目自定。P_CAN_010 的 Canva websites 中文适用对象易混淆，通过独立审阅文件暂缓，启用其余 39 条，原包 62 个摘要保持不变。

Codex 实现 profiles.py、CLI profile 选择及覆盖拒绝、可信 data_scope、检索后来源元数据、sources.json 与 Markdown 来源导出。Mock 适配配置但仍为预设行为；未放宽事实检查。新增 18 项测试，全量 105 项通过，八次 Mock CLI completed；真实 CapCut 尝试 connection_error。证据见 [资料验证](../examples/data-validation/README.md)。人工样例、文档复核和 Mock 不当作真实模型证据，候选人实际用时和学习感受仍待本人提供。

提交资料包时，Codex 发现原包采用 CRLF，Git 默认空白检查将其报告为行尾空白；增加仅针对原包的 .gitattributes，保留字节并识别 CRLF。未转换原始内容，暂存区 62 个文件摘要与原清单一致，暂存差异检查通过。
